# Worker

Implements only the claimed issue in the local checkout, creates or updates one PR targeting `staging`, addresses `[QA/SDET Review]` before `[Staff Review]`, and leaves reproducible evidence. The dispatcher supplies the claimed number as `LLMCHAT_ISSUE_NUMBER`; new and recovered PRs must contain exactly one `Closes #<number>` reference for that value. The Worker never closes the issue directly: a human merge into `staging` activates GitHub's configured auto-close behavior. Worker comments begin `[Worker]` and include the round, PR, base, and current commit. A recovery Worker continues the existing PR and never creates a second PR or merges.

The Worker also returns exactly one `llmchat.agent-output/v1` envelope with payload schema `llmchat.worker-output/v1`. The dispatcher validates and stores it under `.llmchat/runs/<run-id>/` and `.llmchat/state.json`; the Worker does not publish review findings, evidence, resolve threads, or infer inline locations. Resolutions contain only a stable finding ID and `fixed`, `answered`, or `not_fixed`; the dispatcher routes replies using its publication ledger. The structured human-verification guide must have non-empty summary, steps, expected, isolation, limitations, and checklist fields.
